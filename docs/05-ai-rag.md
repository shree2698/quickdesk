# QuickDesk - AI & RAG Pipeline

QuickDesk leverages the Google Gemini model family and LangChain to automate ticket sorting and drive self-service information retrieval.

---

## Why AI
Traditional helpdesks rely on manual triage by dispatchers and require users to hunt through static wikis. QuickDesk integrates AI to:
1. **Reduce Time-to-Triage**: Instant categorization and assignment.
2. **Deflect Support Load**: Interactive chat answers questions instantly.
3. **Enhance Resolution Quality**: Agents receive recommended drafts.

---

## LLM Selection
- **Classification & Chatbot**: `gemini-2.0-flash` is used due to its high speed, low latency, and token-efficiency.
- **Agent Copilot Suggester**: `gemini-2.0-flash` is used for context comprehension when generating long, detailed email/chat drafts that require analyzing complex ticket history logs.

---

## Prompt Engineering & Guardrails
To prevent hallucinations, the model is strictly constrained:
- "Answer the user question *only* using the provided context blocks. Do not use outside knowledge."
- "If the answer is not explicitly present in the context, respond: 'I'm sorry, but I cannot find that information in our company documentation. Would you like me to open a ticket for you?'"
- "Maintain a professional, helpful corporate IT/HR support tone."

---

## Category & Priority Prediction
When a ticket is created, the title and description are processed by `gemini-2.0-flash` using structured JSON schema prompts.

### 1. Category Prediction
The model analyzes context and assigns the issue to one of the following enums:
- `IT`: Software, hardware, networking, credentials.
- `HR`: Benefits, leave policies, job roles, employee conflicts.
- `FINANCE`: Reimbursements, salary, tax forms, software subscriptions.
- `GENERAL`: Facility access, general feedback.

### 2. Priority Prediction
Priority is triaged using rule-based metrics mapped through prompt engineering:
- `URGENT`: Issues affecting whole offices or business-critical lines (e.g., "Main database down", "Office internet offline").
- `HIGH`: Major issues affecting single users block productivity (e.g., "Cannot login to work computer", "VPN auth fails repeatedly").
- `MEDIUM`: Annoyances that can be worked around (e.g., "Macbook sound is scratchy", "Monitor flickers occasionally").
- `LOW`: Queries, questions, or non-blocking issues (e.g., "How do I request an extra keyboard?").

## Knowledge Base Processing
Corporate policies are uploaded via the admin UI and stored in the database, with files saved under `backend/uploads/knowledge-base/`.

### 1. Chunking Strategy
- **Splitter**: LangChain's `RecursiveCharacterTextSplitter`.
- **Chunk Size**: 1000 characters.
- **Overlap**: 200 characters (ensures concepts aren't lost at split points).
- **Separators**: Paragraphs (`\n\n`), sentences (`\n`), spaces (` `), and empty strings (`""`).

### 2. Embeddings
We use the **`gemini-embedding-001`** model via the Gemini API to convert each text chunk. We slice the output to a **768-dimensional floating-point array**.

---

## Vector Store & Retrieval
Embeddings are stored in PostgreSQL using the `pgvector` column type.

### 1. Vector Store Setup
```sql
CREATE EXTENSION IF NOT EXISTS vector;

CREATE TABLE "knowledge_base_chunks" (
  "id" TEXT PRIMARY KEY,
  "knowledgeBaseId" TEXT REFERENCES "knowledge_bases"("id") ON DELETE CASCADE,
  "content" TEXT NOT NULL,
  "embedding" vector(768) NOT NULL,
  "chunkIndex" INTEGER NOT NULL
);
```

### 2. Similarity Search Query
When a user asks a question, the query text is embedded and compared against stored chunks using the cosine distance operator (`<=>`). We fetch the top $k = 4$ matching chunks:
```sql
SELECT content, metadata, (1 - (embedding <=> $1::vector)) AS similarity 
FROM "knowledge_base_chunks" 
ORDER BY embedding <=> $1::vector ASC 
LIMIT 4;
```

## Prompt Template & Generation
The retrieved chunks are injected into a prompt template alongside the user's question:

```text
You are QuickDesk AI, an internal support assistant.
Answer the user's question using only the context blocks below.
Cite the source article name next to the information you present.

[Context Chunks]
Source: VPN Setup Guide
"1. Download the VPN Client from the Software Portal. 2. Install application."

Source: Password Reset Policy
"Accounts lock after 5 failed attempts. Contact IT Support to unlock."

[Question]
My VPN won't connect and I think I typed the wrong password. Help?

[Answer]
```

---

## Citation & Verification
Every answer generated by QuickDesk references its source to build trust and allow manual lookup:
- In-text citation formatting is enforced: `"...[VPN Setup Guide]."`
- The API response matches citation markers with database IDs, allowing the frontend to render clickable buttons linking to the corresponding policy document.

---

## Fallback Strategy
If the highest similarity score in the database lookup is below a threshold (e.g., Cosine Distance $> 0.6$ or Similarity $< 0.4$), the RAG system triggers the fallback flow:
1. It does not send the query to Gemini.
2. It returns: `"I couldn't find a direct match in our documentation. Would you like me to create a support ticket or put you in touch with an agent?"`
3. The UI presents a "Create Ticket" button, pre-populating fields using the chat history.

## Future Improvements
- **Multi-Turn Chat History**: Adding session buffers to enable context-aware conversations (remembers previous sentence context).
- **Self-Correcting Feedback Loops**: Allowing agents to flag bad RAG answers, feeding the feedback back to improve chunk formatting.
- **Auto-Summarization**: Generating ticket summaries when escalating chat sessions to human queues.
